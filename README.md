# HER UNIVERSE · 她的宇宙

**在无数个平行宇宙里，我依然会选择遇见你。**

一个可以继续生长的私人数字宇宙：通过星球探索回忆、时间、小游戏、情书与共同愿望。首版采用轻量星空、原创插画和 CSS 动画，优先照顾手机与 iPad。

准备上线时，直接阅读 [Vercel 部署步骤](docs/DEPLOY_VERCEL.md)。

只有手机、暂时不正式上线：打开 [手机私密预览入口](https://codespaces.new/enshiken614-oss/RANRAN?quickstart=1)，按 [手机预览说明](docs/PHONE_PREVIEW.md) 操作。仓库已配置自动安装和启动，端口保持私有。

姓名、日期与真实回忆尚未提供，仓库仅保留待填写内容和明确标注的示例。先在本地查看，再替换为自己的内容。项目不会自动替你发布网站。

## 先了解三个区别

1. **本地示例与线上私人网站不同。** 开发模式未设置口令时可查看示例；生产模式缺少访问保护配置时拒绝开放内容。
2. **本机保存与双人同步不同。** 收藏、愿望、草稿和探索进度只保存在当前浏览器。更换设备、无痕模式或清理网站数据可能导致丢失。
3. **日期解锁与保密不同。** 首版信件与胶囊的日期显示采用设备时间，不能阻止修改时间或查看已加载数据。真正定时保密的内容需要后台存储和服务端时间校验。

## 一、在电脑运行

需要 Node.js 22 或更新的受支持版本、npm 与 Git。建议使用 Node.js LTS。

在项目文件夹打开终端：

```bash
npm ci
npm run dev
```

在浏览器打开终端提示的本地地址。按 `Ctrl + C` 停止服务。不要把无保护的开发服务开放到互联网。

### 启用访问保护

复制 `.env.example` 为 `.env.local`，填写：

```dotenv
UNIVERSE_ACCESS_CODE=你们专用的长口令
UNIVERSE_SESSION_SECRET=至少32字符的随机密钥
```

随机密钥可在自己的终端生成：

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

把输出复制到自己的 `.env.local`，不要粘贴到聊天、前端配置或 GitHub。`.env.local` 不应提交到 Git。

访问口令至少 8 个字符，建议使用更长且不重复的口令。更改变量后重启服务。生产环境必须同时设置这两个变量；口令或密钥过短也不会开放内容。更换任一凭据会令旧会话失效。

部署时可另外设置 `UNIVERSE_SITE_URL`，填写完整的网站来源地址，例如 `https://你的域名`，用于 API 来源校验。不要带路径。

## 二、个性化内容入口

打开 **`src/config/ourStory.ts`**。内容集中在这里，界面位于 `src/components/`。改文字一般不必改组件。

修改时保留引号、逗号与方括号。可以复制一条现有示例再改内容，完成后运行 `npm run typecheck` 检查格式。

| 想修改什么       | 配置位置        | 提醒                         |
| ---------------- | --------------- | ---------------------------- |
| 双方姓名、昵称   | `identity`      | 可保留待填写，不要编造       |
| 恋爱日期、生日   | `identity`      | 未填写用 `null`              |
| 时区             | `timezone`      | 默认 `Asia/Shanghai`         |
| 主题颜色         | `theme`         | 保持文字对比度               |
| 开场欢迎语       | `intro`         | 简短，适合手机阅读           |
| 最终告白         | `confession`    | 用于终极彩蛋                 |
| 照片、视频与故事 | `memories`      | 见下面的媒体说明             |
| 纪念日           | `anniversaries` | 区分每年重复和一次性         |
| 默契题库         | `quiz`          | 答案序号从 `0` 开始          |
| 情书             | `letters`       | 日期展示锁不是保密措施       |
| 初始愿望         | `wishes`        | 浏览器编辑只保存本机         |
| 彩蛋条件与奖励   | `secrets`       | 新条件类型需同时增加判断逻辑 |
| 环境声音开关     | `music`         | 必须由用户点击才开始         |

### 日期填写

- 普通日期用 `YYYY-MM-DD`，例如 `2027-01-01`；这只是格式示例。
- 生日支持 `MM-DD`，无需为倒计时提供出生年份，也支持完整日期。
- 按配置时区计算日期边界。实时读数依赖设备时钟，设备时间错误会影响显示。
- 生日和周年寻找下一次发生日期。2 月 29 日在非闰年按 2 月 28 日处理。
- 无效、未填写的日期显示待配置状态，不用虚构日期生成数字。

### 添加照片、视频与故事

**`public/` 中的文件应视为公开资源，不要放私人照片、视频或录音。** `public/art/` 只放项目原创示例插画。

私有媒体通过受访问保护的 `/api/media/` 路由读取：

1. 在项目根目录 `private-media/` 放入素材，如 `first-trip.webp`。建议使用没有空格的英文文件名。
2. 在 `memories` 复制一条示例，把 `src` 改为 `/api/media/first-trip.webp`，填写标题、日期、地点、分类和故事。
3. 照片使用 `type: 'image'`；视频使用 `type: 'video'`，`poster` 可指定封面。
4. 登录后检查能否打开；退出后确认私有媒体链接拒绝访问。
5. 上传前可移除 EXIF 中的 GPS 信息并压缩图片。建议长边约 1600–2200 像素；长视频不适合直接放 Git 仓库。

替换为真实内容后，把这条回忆的 `isExample` 改为 `false`（或删除该字段），页面就不再标记为示例。愿望也使用同样的标记。

`private-media/` 默认被 Git 忽略，避免意外提交。只放在本机的文件不会自动出现在 Vercel，部署时可选：

- **少量素材、私人仓库：** 确认 GitHub 仓库私有且协作者可信后，明确选择加入素材，例如 `git add -f private-media/first-trip.webp`。Git 历史会保留文件，后来删除并不能清除历史。
- **较多照片或视频：** 使用私有对象存储，由媒体 API 验证会话后代理读取或签发短期链接。这需要增加存储适配与凭据；首版没有云端上传或自动同步功能。

Vercel 运行时文件系统不能当作永久相册，不要依赖函数执行期间临时写入的文件保存回忆。

### 添加情书、纪念日与小游戏题目

在 `letters` 复制一封示例，修改唯一 `id`、标题、预览、正文与 `unlockDate`；立即可读的信用 `unlockDate: null`。真正到期前保密的文字不要预先发送给浏览器。

在 `anniversaries` 复制一条，填写唯一 `id`、名称、日期和 `recurring`。改完后查看时间星球的下一次日期。

`quiz` 每道题有 `question`、`options`、`answer`、`explanation`。三个选项的答案序号只能是 `0`、`1` 或 `2`。可以写偏好与愿望，不必编造共同经历。寻星、命运星图组件在 `src/components/GamePlanet.tsx`，判断逻辑在 `src/lib/games.ts`。

## 三、数据保存在哪里

| 数据                           | 位置                        | 跨设备自动同步         |
| ------------------------------ | --------------------------- | ---------------------- |
| 姓名、日期、初始故事与情书     | 配置文件，随版本部署        | 更新网站后看到同一版本 |
| 照片、视频                     | 私有媒体目录或后续私有存储  | 取决于部署存储         |
| 收藏、愿望编辑、草稿与探索进度 | 当前浏览器本地存储          | 不能                   |
| 登录会话                       | 最长 7 天的 HttpOnly Cookie | 各浏览器分别登录       |

本地浏览器数据可能被同一设备的其他使用者看到，退出登录不会自动删除这些数据，访问保护也不会加密浏览器存储。重要文字请另外备份，不要把网页当作唯一保存位置。

双人共同编辑需要数据库、两人的独立身份认证与访问控制，例如 PostgreSQL / Supabase 加服务端授权。每次读写都应验证权限；真正时间锁也应由服务器判断，不能只隐藏按钮。

## 四、GitHub 与 Vercel 部署

### 1. 检查仓库权限再提交

建议使用私人 GitHub 仓库。到仓库 Settings 查看可见性，不要为部署把私人仓库改为公开。公开 Git 历史中的内容无法用网站口令保护。

不要提交 `.env.local`、密钥、家庭地址或不希望 GitHub 协作者看到的资料。检查完成后，用自己的 Git 工具提交并推送：

```bash
git add .
git commit -m "Build HER UNIVERSE"
git push
```

分支或权限未配置时按 GitHub 给出的指引操作。项目不会自动替你推送、合并或部署。

### 2. 导入 Vercel

1. 登录 Vercel，选择 **Add New → Project**，连接 GitHub 并选择仓库。
2. 框架选 **Next.js**，根目录保持项目根目录，使用锁文件安装依赖。
3. 在 Environment Variables 设置 `UNIVERSE_ACCESS_CODE` 和 `UNIVERSE_SESSION_SECRET`。Production 与需要使用的 Preview 环境都要配置。**不要添加 `NEXT_PUBLIC_` 前缀。**
4. 确认媒体已通过受保护且可部署的方式保存，再点击 Deploy。
5. 部署后用无痕窗口检查：未登录无法读私人内容和媒体，错误口令无法进入，正确口令能登录。
6. 检查手机、iPad、照片、游戏与文字，再把地址发给她。

Preview 也是部署环境，应有同样保护。访问保护未经实际验证前，不要上传真实私密内容。

### 3. 使用自己的域名

Vercel 项目 → Settings → Domains → 添加域名。到域名注册商按 Vercel 显示的记录设置 DNS，不要猜 IP。等验证与 HTTPS 生效后，再检查新域名登录和媒体读取。

### 4. 更新网站

改配置或代码 → 本地检查 → 提交 GitHub → Vercel 构建。先看 Preview，确认后合并到生产分支。Vercel 可回滚旧部署。清理本机浏览器数据不会更新别人的设备或配置文件。

## 五、手机与 iPad 维护

少量改字：在 GitHub 打开 `src/config/ourStory.ts` → 编辑 → 改文字 → 提交。不要删除结构标点；建议用分支和 Preview 检查。

加文件或改功能：打开 GitHub Codespaces，在浏览器里使用编辑器和终端，运行同样的检查命令。iPad 配键盘更方便。大量照片与视频更适合私有存储。

密钥只在 Vercel Environment Variables 管理，不要通过 GitHub 编辑器写进代码。修改线上变量后重新部署。

## 六、检查与排错

```bash
npm run typecheck
npm test
npm run build
npm run start
```

浏览器流程检查使用 `npm run test:e2e`；第一次需要按 Playwright 提示安装浏览器。以上是运行方法，**不代表检查已经通过**；实际结果见交付说明与终端输出。

本次实际执行结果见 [验收记录](docs/VALIDATION.md)。开发与生产构建分别使用 `.next-dev/` 和 `.next/`，可以同时运行。代码格式可用 `npm run format` 统一整理。项目将 PostCSS 固定到兼容的已修复版本，更新依赖时请保留安全检查。

| 问题                     | 检查方式                                                |
| ------------------------ | ------------------------------------------------------- |
| 生产网站显示访问配置提示 | 设置两个服务端变量，确认密钥长度，重新部署              |
| 正确口令无法进入         | 检查变量所属环境、HTTPS 与 Cookie；不要把口令打印到日志 |
| 时间显示待填写           | 配置尚无真实日期，这是预期状态                          |
| 图片变为替代插画         | 查文件名大小写、登录状态、部署是否包含文件              |
| 另一台手机没有新增愿望   | 本地存储不自动同步                                      |
| 改文字后未更新           | 查是否保存、提交并部署到当前分支                        |
| 动画减少或无自动声音     | 减少动态效果设置生效；声音需主动点击                    |

## 七、结构与扩展

```text
src/app/                 页面、服务器入口与 API
src/components/          宇宙与各星球组件
src/config/ourStory.ts   个性化内容
src/lib/                 时间、游戏和访问逻辑
public/art/              公开的原创示例插画
private-media/           私有媒体，默认不提交
tests/                   自动检查
docs/PRODUCT.md          产品、视觉与技术规划
```

增加星球时，同时添加导航数据、场景入口、内容组件与可访问名称，并把完成事件接入彩蛋逻辑。仅增加一个没有行为的按钮不算完成。

采用 Next.js App Router、React、TypeScript、Lucide 与自定义 CSS。轻量星空和 SVG/CSS 替代大型 WebGL 场景，减少手机 GPU 与电量负担。插画为原创示例，不冒用真实照片或未经授权的歌曲。

## 隐私边界

访问凭据由服务器验证，会话使用签名 HttpOnly Cookie，私有媒体逐次授权。个人配置通过受保护的服务端数据路径传给已登录页面，不能直接把私密内容打包进公开 JavaScript。

Cookie 使用生产环境 Secure、SameSite Strict 和 HttpOnly 设置。登录有每个运行进程内的失败限流；Vercel 多实例或冷启动不能共享此计数，对互联网开放时建议另外配置 WAF 或持久限流。

这仍是两人共享口令的轻量系统，不等同于独立账户、端到端加密或企业权限系统。托管平台、仓库拥有者和授权协作者可能访问内容；已下载到浏览器的内容无法远程收回。对更高要求，增加独立账户、多因素认证、私有存储、持久限流和备份。

首版不默认发布真实资料，不把本地保存包装成云端同步。了解这些边界后，再替换为你们自己的内容。
